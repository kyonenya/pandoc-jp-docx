# Word の和欧間アキと、記号が挟まったときの破綻

## 概要

Word は半角英数字と和文の間にアキを自動で入れる。ところがプライム記号や丸括弧が挟まると、記号の側のアキだけが入らなくなり、左右非対称な組版になる。

```
世界1において    → 世界 1 において     （両側に入る）
世界1′において   → 世界 1′において     （右が入らない）
これをP(P)と定義する → これを P(P)と定義する （右が入らない）
世界(2)において  → 世界(2)において     （両側とも入らない）
```

これは Word の不具合ではなく、次の三つの仕様の重ね合わせから生じる。

1. 和欧間アキを制御するのは段落プロパティの `w:autoSpaceDE` / `w:autoSpaceDN` で、既定は有効
2. アキが入るのは **Latin 側が英字・数字のときだけ**で、記号は前後とも対象外
3. Ambiguous 文字を半角幅に固定しても（[filter-half-width.md](filter-half-width.md) 参照）、この判定は変わらない

以下、実測にもとづいて整理する。

## 1. 和欧間アキを制御する OOXML 要素

段落プロパティ `<w:pPr>` に、和欧間アキの自動調整を制御する 2 つの要素がある。

| 要素 | 仕様上の名称 | Word UI での表記 |
|---|---|---|
| `w:autoSpaceDE` | [Automatically Adjust Spacing of Latin and East Asian Text](http://www.datypic.com/sc/ooxml/e-w_autoSpaceDE-1.html) | 日本語と英字の間隔を自動調整する |
| `w:autoSpaceDN` | [Automatically Adjust Spacing of East Asian Text and Numbers](http://www.datypic.com/sc/ooxml/e-w_autoSpaceDN-1.html) | 日本語と数字の間隔を自動調整する |

いずれも省略時の既定値は有効である。本リポジトリの `reference.docx` はこれらを明示していないため、既定が効いている。つまり **アキが入らないのは設定の問題ではなく、Word の判定ロジックそのものによる**。

## 2. 実測の方法

Word の入れるアキは動的なレンダリング処理であり、OOXML には現れない。実際の値を知るには Word にレンダリングさせる必要がある。

本リポジトリには [Microsoft Graph API 経由で DOCX を PDF に変換する仕組み](postprocess-pdf.md) があるので、これで Word 実機の出力を得て、PDF のコンテンツストリームからグリフの x 座標と字幅を取り出し、

```
gap = 次の文字の x − (この文字の x + この文字の字幅)
```

として文字間のアキを求めた。以降の数値はすべてこの方法による実測値である（本文 11pt）。

なお **和文どうしの間にも一律 `+0.24pt` の字間がある**。これは `reference.docx` の `<w:docGrid w:type="linesAndChars" w:charSpace="776"/>`（[Document Grid](http://www.datypic.com/sc/ooxml/e-w_docGrid-1.html)）による文字グリッドの送りで、和欧間アキとは別物である。`+0.24` 前後の値は「アキなし」と読む。

## 3. どこにアキが入るか

| 入力 | 実測 | 判定 |
|---|---|---|
| 世界1において | 世界 `+3.00` 1 `+2.50` において | 両側に入る |
| 世界1′において | 世界 `+3.00` 1 `+0.25` ′ `+0.34` において | **右が入らない** |
| 世界1、という | 世界 `+3.00` 1 `+0.25` 、という | 読点の前は元々不要 |
| 世界1′、という | 世界 `+3.00` 1 ′ `+0.34` 、という | 同上 |
| 「世界1」 | 「世界 `+3.01` 1 `+0.28` 」 | 閉じ括弧の前は元々不要 |
| 「世界1′」 | 「世界 `+3.01` 1 ′ `+0.09` 」 | 同上 |
| （世界2） | （世界 `+3.01` 2 `+0.28` ） | 同上 |
| （世界2′） | （世界 `+3.01` 2 ′ `+0.09` ） | 同上 |
| 世界(2)において | 世界 `+0.25` ( `+0.33` 2) `+0.34` において | **両側とも入らない** |
| これをP(P)と定義する | これを `+3.01` P(P) `+0.12` と定義する | **右が入らない** |

読み取れること。

- 破綻するのは **記号の隣が和文** のときだけである。読点や閉じ括弧が続く場合はもともとアキが不要なので、結果的に正しく見えている。
- `世界1′` の左が空くのは `1` が数字だからで、`′` のおかげではない。だから `世界(2)` のように**記号が直接和文に接すると左も空かない**。
- `これをP(P)` の左が空くのは、`を` の右隣が記号ではなく英字 `P` だからである。

傍点（`**強調**`）の中でも挙動は同じで、アキだけが入らない。プライム自体は半角 2.41pt で正しく描画されている。

## 4. アキが入る条件

`東西X東西` の `X` を差し替えて網羅的に測ったところ、アキが入るのは **Unicode の文字カテゴリが Letter または Number のとき**だけだった。

| | 文字 |
|---|---|
| 入る | `A` `a` `Z` `3` `Ω` `Å` |
| 入らない | `!` `"` `#` `$` `%` `&` `'` `(` `)` `*` `+` `,` `-` `.` `/` `:` `;` `<` `=` `>` `?` `@` `[` `]` `^` `_` `{` `|` `}` `~` `°` `§` `±` `×` `÷` `¶` `·` `¢` `£` `¥` `©` `®` `′` `″` `‴` `–` `—` `'` `'` `"` `"` `…` `‰` `†` `‡` `•` `≠` `≤` `≥` `∞` `√` `∴` `℃` `①` |

つまり **記号は East Asian Width が Ambiguous かどうかとは無関係に、一律で対象外**である。ASCII の `"` や `'` でも同じく入らない。この網羅測定は LibreOffice で行ったが、個別ケース（`′` `″` `‴` `(` `)` `§` `°`）は Word 実機でも同じ結果を確認している。

## 5. アキの量

| 箇所 | 文字サイズ | 和文 → 英数字 | 英数字 → 和文 |
|---|---|---|---|
| 本文 | 11pt | `+3.00` | `+2.25`〜`+2.50` |
| 脚注 | 10pt | `+3.75` | `+2.50` |
| 見出し 2 / 3 | 18pt | `+4.77` | `+4.24` |

- 左右が非対称で、和文側のほうが広い。
- 同じ本文でも `+2.25`〜`+2.50` と揺れる。Word が和文を文字グリッドに合わせるため、行内の位置によって余りが変わる。
- **サイズにおおむね比例する**が、本文 11pt と脚注 10pt の差はグリッドによる揺れに埋もれる。

## 6. 補正の方法

run の文字書式に [`w:spacing`（Character Spacing Adjustment）](http://www.datypic.com/sc/ooxml/e-w_spacing-2.html) を指定すると、その run の文字の後ろにアキが入る。単位は 1/20 pt。

```xml
<w:r><w:rPr><w:spacing w:val="44"/></w:rPr><w:t xml:space="preserve">)</w:t></w:r>
```

Word 実機での検証結果。

| 補正 | 実測 |
|---|---|
| なし | 1′ `+0.34` において |
| `′` に `w:val="50"` | 1′ `+2.87` において |
| `′` に `w:val="55"` | 1′ `+3.12` において |
| `′` に `w:val="60"` | 1′ `+3.37` において |
| `界` と `)` に `w:val="50"` | 界 `+2.50` (2) `+2.84` において |
| `P(P` の `)` に `w:val="50"` | P(P) `+2.84` と定義する |

指定した値がそのまま加算される。自動で入るアキ（`+2.25`〜`+2.50`）に合わせるなら **`w:val="44"`（2.2pt）** が近い。本文で `+2.34`、脚注で `+2.56` となり、いずれも自動アキとの差はグリッドの揺れの範囲に収まる。

うまくいかない方法も記録しておく。

- **空の `<w:t>` を持つ run に `w:spacing` を付ける** — 文字がないので何も起きない
- **極小サイズの半角スペースを挿入する** — スペース文字そのものが残り、幅もフォント依存で不正確

左側（`世界(`）を補正する場合は、記号ではなく **直前の和文 1 文字**の run に `w:spacing` を付ける。`w:spacing` は文字の後ろにしか効かないためである。

## 7. 実装

[`filters/str_rules.lua`](../filters/str_rules.lua) が、`Str` と `Strong` を走査して対象文字を独立した run に切り出し、必要な文字書式を付ける。

| 対象 | 文字 | 付与する書式 |
|---|---|---|
| 半角幅の固定 | `§` `′` `″` `‴` | `<w:rFonts w:hint="default"/>` |
| 全角幅の固定 | `Ⅰ`–`Ⅻ` | `<w:rFonts w:hint="eastAsia"/>` |
| 和欧間アキ | `′` `″` `‴` `(` `)` | `<w:spacing w:val="44"/>` |

アキは「記号 → 和文」「和文 → 記号」の両方向を見て、隣が和文のときだけ付ける。和文の判定はひらがな・カタカナ（`U+3040`–`U+30FF`）と CJK 統合漢字（`U+4E00`–`U+9FFF`）で、句読点・カギ括弧・全角括弧（`、` `。` `「` `」` `（` `）`）はこの範囲外なので自動的に対象から外れる。3 節のとおり Word もこれらの前後にはアキを入れないので、挙動が一致する。

補正量は絶対値なので、`reference.docx` の本文文字サイズを変えたら見直しが必要になる。見出し（18pt）では自動アキの半分ほどになるが、見出しに記号が来る頻度を踏まえて許容している。

### 既知の制限

**親のインライン書式は対象文字の run に入らない。** 対象文字は `RawInline('openxml', ...)` で独立した run になり、その `<w:rPr>` にはこのフィルターが指定する書式しか入らない。

| 記法 | 落ちる要素 | 見え方 |
|---|---|---|
| `*世界(2)において*` | `<w:i>` | `界` `)` だけ斜体が外れる |
| `~~世界(2)において~~` | `<w:strike>` | `界` `)` だけ取り消し線が外れる |
| `[世界(2)において](url)` | `<w:rStyle w:val="Hyperlink">` | `界` `)` だけ文字色・下線が外れる（`<w:hyperlink>` は全体を包むのでリンク自体は効く） |

傍点（`**強調**`）は `Strong` パスが `stringify` した文字列を自前で分割し、全 run に `<w:em>` を付け直すため影響を受けない。`Str` パスは親要素を参照できないので同じことができない。

**判定は `Str` の中で完結する。** `これを**P(P)**と定義する` のように対象記号と和文が別のインライン要素に分かれている場合は補正されない。

## 8. 検証するときの注意

**LibreOffice は Word の代替にならない。** 次の 2 点で挙動が異なる。

- `reference.docx` の `docGrid` があると、LibreOffice では和欧間アキが**完全に消える**。Word ではグリッドがあっても入る。
- LibreOffice は `w:rFonts` の `w:hint` を無視する。半角幅の固定が効いているかを LibreOffice で確認することはできない。

アキ量も Word とは異なり、LibreOffice は 2.20pt 左右対称だった（Word は `+3.00` / `+2.50` の非対称）。

したがって、アキに関する検証は Graph API 経由で Word に PDF 変換させて行う。傾向を見るだけなら LibreOffice でも足りるが、その場合は `docGrid` を除去した比較用ファイルを作る必要がある。
